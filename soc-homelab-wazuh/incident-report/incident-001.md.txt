## Summary

A brute-force RDP attack originating from 192.168.56.109 (Kali Linux) targeted
the Windows 10 endpoint at 192.168.56.108 (DESKTOP-MOSHGPL). After multiple
failed logins, a successful authentication was observed. The attacker then
executed encoded PowerShell which created a suspicious .ps1 script file in the
Windows SystemTemp directory — flagged by Wazuh as Command and Control activity
(Rule 92205, T1105). Discovery commands were also executed to enumerate the system.

## Findings

The attacker brute-forced RDP credentials against DESKTOP-MOSHGPL and successfully
authenticated. Immediately after, encoded PowerShell was executed which created a
suspicious .ps1 script (PSScriptPolicyTest) in C:\Windows\SystemTemp — Wazuh
classified this as Command and Control activity (Rule 92205, level 9). SecEdit.exe
was also observed running under NT AUTHORITY\SYSTEM, exporting security configuration
to C:\Windows\TEMP\secexport.cfg, suggesting further post-compromise enumeration.
The use of the -enc flag indicates deliberate attempt to evade command-line logging.

---

## Recommended Remediation

- Enforce account lockout after 5 failed login attempts
- Block RDP access from untrusted network segments using firewall rules
- Enable PowerShell ScriptBlock logging (Event ID 4104)
- Alert on encoded PowerShell (-enc flag) via Wazuh custom rule
- Monitor writes to C:\Windows\SystemTemp by PowerShell processes
- Audit usage of SecEdit.exe outside of expected admin contexts
- Monitor for sequential discovery commands executed after a new login
